# 前台应用计时诊断（0.5.6 已部署并完成有限实测）

该诊断用于调查 Tiny2D、画布及显示等待；当前板上 **0.5.6-strip-perf-usb** 已显式启用。源码 `CONFIG_LISP_PERF_TRACE` 默认关闭，专用配置在应用配置之后追加 `tests/sdkconfig.perf.defaults`。

## 使用

1. 在终端空闲状态加载并定义应用；提交 `:perf-start`，清空并启动本次 RAM 统计。
2. 单独执行 `(app-run tiny2d)` 或其他应用；按正常方式退出并等待终端恢复。各应用应分别启动统计，不应将多组混在一起。
3. 终端空闲后提交 `:perf-stop`，停止统计并一次输出各项目的样本数和平均／最小／最大微秒。未开始时 stop 会报错，已开始时再次 start 会报错。

**不要在应用运行期间输入 `:perf-stop`**：前台应用占有输入，UART 字节会作为应用按键，TCP 命令也会被应用门控。等待正常退出或用已有 Ctrl-C / TCP `:stop`，确认终端恢复后再提交。诊断命令仅在 opt-in 构建生效，当前 `:help` 不列这些专用命令。

## 指标定义

所有时间为 `esp_timer_get_time()` 的墙钟微秒，**不是 CPU 时间**；包含任务抢占和计时本身的开销。不同任务并发运行，指标重叠，不能简单相加；样本数不同也不能直接比较总和。没有每帧日志，报告只在明确 stop 后输出；开启诊断本身仍会扰动调度和内存访问，目标端开销尚未测量。

| 名称 | 范围与限制 |
| --- | --- |
| `clear`、`rect`、`text` | APP_STEP 回调中每次对应 C 绘图函数的墙钟时长，不含输入解码；初始化/退出回调不计。包含抢占，不是独立 CPU 测量。 |
| `canvas_copy` | 每次 APP_STEP 的 `display.draw()` 墙钟时长，包括健康检查、短锁、画布选择及整画布复制，不仅仅是 `memcpy`。初始化不计。 |
| `callback` | APP_STEP 回调创建完成到回调收尾前的墙钟时长，含解释器和任务调度、嵌套图元调用，不含前置 GC、上下文创建和画布复制。含按键和 tick 回调。 |
| `tick_late` | 空闲 tick 实际被调度时相对目标周期的滞后，`clock_ms` 粒度为 1ms，可能包括任务调度和画布背压；不等于任一单独等待原因。 |
| `backpressure` | 空闲 tick 到期后首次观察画布不可用，至观察其可用的墙钟时长；只记录完整区间。会话切换、退出或测量结束时的未完成区间丢弃，不能据此推断全部等待。 |
| `lcd_frame` | LCD owner 对应用画布的一整帧 `draw_frame` 墙钟时长；可能重复显示同一画布，不能当作应用帧率。失败或测量边界跨越的帧丢弃。 |
| `lcd_render` | 同一 LCD 帧中各条带格式转换时间之和。 |
| `lcd_transfer` | 同一 LCD 帧中各条带提交至 DMA 完成信号返回的时间之和，包含命令、等待和调度，不单是 SPI 总线传输。 |

只测显式 `:perf-start` 到 `:perf-stop` 之间完成的片段；跨启停边界的未完成 span 通过 generation 拒绝，不会混入下次统计。计数饱和后不再累加，总时间溢出时饱和。锁仅保护固定大小聚合，不在 LCD DMA 或像素循环期间持锁；不改变画布所有权、控制门控或 Flash/NVS。

## 离线证据与边界

主机纯状态模型覆盖启停、重复请求、跨代未完成片段、逆序时间、饱和、命令解析和报告容量；两种真实 LispBM 主机模型覆盖计时接线及背压，均不是 FreeRTOS/SPI 实机。full TCP/URL 诊断、诊断 UART 和默认关闭配置已离线构建；默认关闭镜像不链接诊断 API。上游已有 UBSan 对齐诊断仍保留。

0.5.5唯一USB写入及180.073秒只读启动通过后，实际一个TCP连接、一次Tiny2D URL加载、Tiny2D与空present各50回调并分别执行perf-start/stop，计数和输出通过；这是有限实机验证，不代表时钟/锁/堆栈与SPI/DMA并发已全面验收。后续条带转换优化已随0.5.6部署并做相同方法复测；新固件仍须独立冻结准确镜像并取得新hash/实际擦写范围批准，重新做完整预检。不要直接使用开发构建刷机。

## 0.5.6 条带优化前后实测

同方法各50绘制回调（另一次退出tick），墙钟各51个完整样本：

| 指标ms | Tiny2D 0.5.5 | Tiny2D 0.5.6 | 空present 0.5.5 | 空present 0.5.6 |
| --- | ---: | ---: | ---: | ---: |
| LCD整帧 | 197.100 | 182.330 | 178.759 | 170.006 |
| LCD条带转换 | 66.006 | 50.233 | 48.997 | 39.431 |
| LCD提交＋等待 | 130.817 | 131.783 | 129.528 | 130.280 |
| 画布draw/复制 | 32.216 | 33.109 | 32.402 | 32.979 |
| APP_STEP回调 | 57.960 | 57.801 | 15.568 | 15.548 |
| 到期后观察背压 | 86.970 | 70.233 | 78.787 | 69.208 |
| tick滞后 | 97.843 | 82.941 | 79.156 | 69.607 |

Tiny2D条带转换均值减少15.773ms（约23.9%），LCD整帧减少14.770ms（约7.5%）；空present分别减少约19.5%和4.9%。两次短会话含预热/调度/仪表扰动，非纯CPU、物理LCD FPS或长期稳定性验证；不同任务的重叠项目不能相加。ILI9341 [V1.11数据手册](https://cdn-shop.adafruit.com/datasheets/ILI9341.pdf)第18.3.4节给出四线SPI写周期最小100ns（10MHz，表列温度/电压条件），因此20MHz属于超规格，不能作为默认安全提速。
